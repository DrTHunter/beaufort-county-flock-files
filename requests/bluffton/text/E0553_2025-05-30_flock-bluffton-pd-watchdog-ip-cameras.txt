You don't have to have a user account in Flock already for it to work, if you login using SSO for your first time then it will create you a new account in Flock. The new users will default to a "patrol" role in Flock.
 
Check the following:
 
1. “User assignment required?” = No
If enabled, only users explicitly assigned can access the app — which blocks JIT provisioning for unassigned users.
To check:
Azure AD → Enterprise Applications → [Flock App] → Properties
Set User assignment required? to No
 
2. SAML Attributes Must Include Email
Flock needs to match or create users using a unique identifier — usually the email address in the SAML assertion.
Ensure Azure is sending:
NameID = user email (or user principal name, if that’s how Flock matches accounts)
OR a custom claim like email = user.email
To verify:
Azure AD → Enterprise Applications → [Flock App] → Single sign-on → Attributes & Claims
Ensure at least one claim contains a valid email address for the user
3. Claims Are Sent Even for New Users
Sometimes, custom claims are scoped only to assigned users or groups. Ensure that your claims (especially the email) aren’t conditional on group membership or a dynamic rule.
4. The User’s Azure AD Profile Is Properly Populated
If user.mail is blank (which can happen with service accounts or synced accounts from on-prem AD), the email claim may not be populated, and Flock won’t create the user.
To check: Go to Azure AD → Users → [select user] → Ensure Email or UserPrincipalName is correctly filled out
 
Test with a brand-new AD user
If you have a test user who is not assigned to the app but exists in AD and has the correct email fields, try signing in via the SSO login URL. If they’re blocked, the sign-in logs should tell you exactly why.
Let me know if you have any questions or concerns.
